## 产品结构

工作台围绕一台 GPU 实例组织，应用作为可配置的运行单元。首版只接入已有的 Google Colab，同一套界面运行在 Windows 和 macOS。ComfyUI 是首个内置应用，不再决定整个客户端的导航和状态。

| 页面 | 用户要解决的问题 |
| --- | --- |
| 工作台 | 启动/释放实例，确认 GPU、分配地区和计费，打开已就绪的应用 |
| 应用 | 管理 ComfyUI、Python 任务或自己的 Web 服务；选择是否随实例启动 |
| 文件与同步 | 查看按应用扫描的清单、文件来源与目标、同步结果和缓存时间 |
| 活动记录 | 查看申请、连接、应用和同步的独立事件；错误保留并可导出 |
| 设置 | 选择账号、存储目录、访问范围和关闭窗口行为 |

界面采用固定标题栏、侧栏、内容框架与底部状态栏。桌面尺寸不出现整窗滚动；长文件列表和日志只在各自内容区滚动。Windows 标题栏与 macOS 标题栏分别适配，内容结构共用。小宽度预览用于检查溢出，产品主目标仍是桌面。

## 客户端内部连接管理

按用户补充要求，不依赖外部 SSH 客户端、系统 ssh 可执行文件、独立终端或手动隧道命令。用户只面对应用入口、任务进度和日志。

现有 Colab 的受保护连接能力可以作为内部通道继续研究复用；是否内部使用 SSH 协议属于实现选择。内置协议客户端需要完成鉴权、远程执行、应用端口映射、断线重连与生命周期管理，不能简单把系统 ssh 命令藏起来就算完成。

默认入口只绑定本机，局域网访问作为显式开关。应用的访问 URL、端口和健康检查属于应用配置。通用连接层不应写死 ComfyUI 的 `/system_stats` 或 `18188 → 8188`。

## 状态与数据约定

四类状态独立：

- 实例：未创建 / 申请中 / 运行 / 释放中 / 已释放 / 待确认。
- 应用：未部署 / 准备中 / 运行 / 已停止 / 失败。
- 连接：连接中 / 可用 / 中断 / 重连中。
- 同步：待同步 / 进行中 / 已校验 / 失败。

请求超时和连接中断不能推断为已关机。HTTP 503 表示服务暂时不能完成请求；没有结构化依据时，不断言“资源池已满”。只有查询确认实例已释放和计费已停止，界面才显示停止计费。

错误作为独立事件保留，不由下一次状态刷新清除。停止应用不释放机器，计费继续。关闭窗口也不等同于关机；正式版通过 Windows 托盘 / macOS 菜单栏持续呈现状态（本稿不实现系统托盘）。

模型列表、文件数量和大小来自扫描结果，不在视图里写死。区分“配置了哪些下载”“实例本地已发现”“云盘已保存”；关机或读取失败时标明缓存、扫描时间和待核验状态，不能用空数组代替错误。交互稿数据集中在 `index.html` 的 `demo-data` 中，所有列表和合计由该数据生成；这只是数据驱动的演示，不是实时扫描实现。

关机顺序为：停止产生新文件 → 同步已配置目录 → 在目标端验证保存结果 → 释放实例 → 确认停止计费。任何保存步骤失败都保留实例，明确继续计费，允许重试。现有实现尚不能保证这套约定，尤其需要纠正同步失败后仍可能释放实例的路径，以及以网络安静代替远端持久化确认的判断。

## 现有代码的复用与改造

| 范围 | 已存在的能力 | 通用化需要做的工作 |
| --- | --- | --- |
| Colab 接入 | OAuth、分配/查询/释放、地区解析、Drive 授权 | 与具体应用解耦；保留账号选择和真实服务错误 |
| 云端准备 | 环境恢复、固定版本依赖、HF 下载、文件同步 | 保留 ComfyUI 安装逻辑，作为应用配方；通用框架只管理执行生命周期 |
| 实例启动 | `tool_up_comfy_linux` 串起全部步骤 | 实例启动和应用启动分开；实例就绪不依赖 ComfyUI |
| 连接 | WebSocket 通道 + 系统 ssh 子进程、ControlMaster、pkill | 改为内置协议客户端；跨平台进程/连接生命周期；取消外部 ssh 依赖 |
| 访问入口 | 固定本机 IP、端口和 ComfyUI HTTP 探测 | 按应用建立入口、端口冲突检查、健康探测；显式配置局域网共享 |
| 桌面界面 | SwiftUI / AppKit、本机文件状态和命令调用 | 新建共用跨平台界面；替换 NSWorkspace、NSPasteboard 等平台调用 |
| 路径与打包 | 固定 `/Users/...`、`/Volumes/...`、Python 路径 | 通过系统目录和用户指定数据盘定位；随安装包提供运行时 |
| 日志与状态 | 当前命令输出 JSON 加说明文字、单一 phase | 结构化事件流；独立实体状态；错误持久保留；流式读取与取消 |

源代码定位：

- `../colab_mcp_server.py`：`_ssh_base_cmd`、`_start_tunnel`、`tool_probe`、`tool_up_comfy_linux`。
- `../cloud_bootstrap.py`：环境准备、模型和用户文件处理、Drive 同步。
- `../ComfyCloudApp/Sources/CloudController.swift`：平台调用、单一工作站状态、命令执行。
- `../ComfyCloudApp/Sources/Models.swift`：可复用的数据含义；Swift 类型本身不直接用于跨平台 Web 界面。

## 建议落地方式

首个增量已采用 Tauri 2 + React / TypeScript + HeroUI 构建共用界面，由 Rust 后端负责 OAuth、安全存储、本地状态和受控 IPC；令牌不交给前端。已有 Python 环境准备逻辑和新的守护脚本作为云端资源随包提供，已接入内置上传与部署；不需要用户安装或运行本地 Python 控制服务。

不要求用户安装 Python、SSH 或 Node。内置连接实现先验证 Colab 受保护通道在 Windows 的兼容性、重连和流控，再决定保留的库与封装方式。这个方案未进行 Windows 编译或实机测试，本设计稿也不是 Windows 可执行程序。

最小应用配置包括名称、类型（长期服务 / 一次任务）、启动方式、运行目录、访问端口、健康检查、下载文件清单、保存目录和是否随实例启动。内置 ComfyUI 配方继续保留已确定的版本、插件和文件来源，不引入通用插件市场，也不预先建设多个云供应商框架。

实施顺序：先做共用界面和结构化状态通道；再将 ComfyUI 提取为首个配方并接入内置连接；最后验证 Windows 打包、关机持久化和故障恢复。现有 Swift 版本在新客户端达到功能一致前继续保留。
