# Cloud Deck · 浏览器登录与首次使用

2026-11-14 · 设计稿 v03 · Windows / macOS

## 这次要解决什么

用户安装一个桌面客户端，在自己的浏览器里选择 Google 账号，然后直接启动应用。日常使用不要求用户打开 Colab 笔记本、复制授权码、配置 SSH、安装 Python 或编写启动单元格。首次接入 Google Colab，ComfyUI 是第一个可直接启动的应用。

交互稿入口为 `onboarding.html`。它与 `index.html` 的通用工作台互相链接；所有账号、权限检查、实例、保存结果都是演示，不会访问 Google、收集密码、申请 GPU 或修改现有授权。

## 用户旅程

| 阶段 | 用户动作 | 客户端行为与成功条件 |
| --- | --- | --- |
| 连接账号 | 点击“使用 Google 账号继续” | 打开系统默认浏览器，Google 提供账号选择；登录本身不申请实例 |
| 等待返回 | 在 Google 页面选账号、授权 | 应用保持等待，提供重新打开和取消；浏览器成功后自动回到应用，无法激活窗口时可手动返回 |
| 确认可用 | 确认账号，必要时更换 | 分别显示身份登录、Colab 权限/服务访问、可用计算权益；全部确认后才继续 |
| 选择应用 | 默认 ComfyUI；确认 GPU 和保存位置 | GPU 来自账号当次查询结果，原型选项仅为演示；默认自己的 Google Drive，不要求填写 SSH 或运行命令 |
| 确认启动 | 点击“确认并启动” | 明确实例分配成功即可能计费，GPU/地区按实际分配，尚未就绪也可能计费 |
| 首次准备 | 必要时再次在浏览器授权 Drive | 分配实例 → 连接保存位置 → 确认可以读写 → 准备应用 → 建立入口 → 健康检查 |
| 开始使用 | 点击“打开 ComfyUI” | 正式版打开本机受控入口；原型显示演示说明。之后可进入已有完整工作台 |

Drive 的授权与 Google 身份登录分开处理。现有实现通过运行时的挂载流程授权，因此不能在实例尚未建立时承诺挂载已完成，也不能承诺只登录一次就永远不再授权。用户拒绝 Drive 或连接失败时，不启动会产生新文件的应用；已经分配的实例仍显示计费中。

再次打开客户端：安全刷新授权 → 重新查询实例 → 恢复连接与已选工作空间。正常情况下不再走欢迎页；授权失效时保留上次工作空间、文件缓存和事件。第一版每次只激活一个 Google 账号，不做账号池或自动轮换。

## 浏览器登录的设计机制

选择 Google 官方桌面应用 OAuth 授权码流程，配合 PKCE S256、随机 state、OIDC nonce；使用系统浏览器和临时 loopback 回调端口，Windows/macOS 共用实现逻辑。

1. 产品方创建自己的 Desktop app OAuth 客户端及同意屏幕，配置所需范围和公开发行资料。**普通用户无需创建 Google Cloud 项目，也无需提供 client ID 或密钥。** 此配置不等于要求用户采用 Vertex/GCP 计费方案。
2. 本地控制服务先在 `127.0.0.1` 的随机可用端口监听固定回调路径，再打开授权 URL。端口仅绑定回环，不能绑定所有网卡。
3. 每次生成独立的 verifier、state 和 nonce。明确“换账号”时使用 Google 支持的账号选择行为，不把上次账号静默当作用户选择。账号选择参数须在自有桌面客户端中验证。
4. 回调只接收当前未取消、未超时请求。验证路径、state、错误参数，授权码只消费一次，并用 verifier 兑换令牌。OIDC 验证 issuer、audience、有效期与 nonce。
5. 账号归属使用验证后的 `issuer + sub`，邮箱只作显示。拒绝授权、重复/迟到回调、超时、刷新失效分别处理，不能写入别的账号会话。
6. 成功后浏览器显示“已连接，可以回到 Cloud Deck”，不展示令牌；应用自动前进，提供手动返回的正常退路。
7. refresh token 留在本机控制服务和系统安全存储：macOS Keychain、Windows Credential Manager/DPAPI。前端、日志、URL、导出包不持有令牌。桌面 OAuth client secret 不能被视为机密保护措施。
8. 关闭回调监听，清理一次性授权上下文。原型的浏览器对话框只是流程演示，正式产品不得用内嵌 WebView 承载 Google 登录。

不采用已废弃的复制授权码/OOB 流程。桌面回环回调仍受支持；不要混淆移动端 loopback 限制。Google 安装应用指南说明不支持 incremental authorization，因此不预设网页端的增量授权行为：身份登录、计算接入和运行时 Drive 的实际范围与授权次数，必须分别验证。

## 状态与恢复

身份授权、Colab 能力、实例、应用、连接、同步分别存储，不用单一 `loggedIn` 决定能否启动。

| 情况 | 显示与动作 | 不得发生的行为 |
| --- | --- | --- |
| 用户取消/拒绝 | 保留登录入口，可重新选账号 | 不标记登录成功，不申请实例 |
| 等待超时 | 显示本次请求已失效，重新开始授权 | 不接收旧请求的迟到回调 |
| 浏览器没打开 | 重新打开；正式版提供同一次有效请求的登录链接 | 不让用户粘贴密码或授权码到客户端 |
| 登录成功，Colab 查询失败 | 身份保留，能力“待确认”，可重试 | 不推断账号免费、不显示零余额、不启用启动 |
| 明确权益不足 | 明确服务返回原因，可更换账号或查看 Colab 方案 | 不把免费档包装成可绕过限制的 GPU 服务 |
| 授权被撤销，实例曾在运行 | 要求重新登录同一账号，云端/计费待确认 | 不显示“已关机”或清除错误 |
| 实例启动后 Drive 授权失败 | 应用尚未启动，保存未连接，实例继续计费；可重试或走释放确认 | 不在未连接保存位置时开始生成数据 |
| 已有实例，用户要切换账号/退出 | 保留当前账号与控制权，先引导保存并关机 | 不静默遗留正在计费的实例，不删除唯一控制凭据 |
| 保存并关机失败 | 保留实例，明确继续计费，允许重试 | 不把同步网络安静当成远端保存证明 |

原型账号面板对运行中/待确认的机器阻止切换或退出；前往工作台执行保存关机流程。设计允许用户查看模板与帮助，但在确认前不发起真实云端操作。

## 公开发行前必须验证的接入边界

浏览器登录本身有标准实现。**2026-11-14 已用当前 Google 官方 Colab CLI 客户端配置完成真实浏览器 OAuth、自动本机回调、令牌刷新及 Colab 只读访问，全部通过，详见 [OAuth 实测记录](../OAUTH-TEST.md)。** 因此，当前客户端配置的浏览器登录机制已证实可行。

旧 Python 控制器继续保留为迁移基线；新 Tauri 客户端已在 `../client/` 集成 Rust 浏览器登录、安全存储、刷新和 Colab 接入，详见 [客户端说明](../client/README.md)。Rust 版真人浏览器授权、安全存储、跨进程恢复和刷新已通过；Colab 用量解析及实际部署仍在联调。此前完整的只读访问证据来自独立 `oauth_probe.py`，不能混淆两轮结果。**产品方独立注册的 OAuth 客户端对任意外部用户的计算授权仍未验证。** 现有 `/tun/m/*` 和受保护连接是已研究的 consumer 路径，不能表述为已验证的稳定公开 SDK。

设计可先确定，但公开发行的技术验收必须包括：

- 使用产品自己的客户端与独立测试账号验证合法所需 scope、账号切换、查询、分配/释放、运行时连接及 Drive 授权；不要分发现有个人 token 或复用来路不明的第三方 OAuth 客户端。
- 明确 Google 品牌、首页、隐私政策与授权范围审核要求；测试模式的用户与令牌限制不能当作生产能力。
- 根据服务真实能力和官方政策判断可用性，不根据邮箱、订阅名称或登录成功猜测。账号授权无法通过验证时停止接入并展示原因，不以 cookie 抓取、隐藏网页点击或伪装官方客户端作为回退。
- Colab FAQ 对免费档中绕开笔记本、主要通过 Web UI 进行内容生成及远程操作有限制；付费且有正计算余额可解除其中限制，但不保证 GPU 可用性，也不等于可以长期托管任意公共服务。首版定位个人交互式计算，原型的“自定义服务”不能承诺公共托管能力。
- 账号、目录、运行时归属隔离；只在用户点击并确认启动时分配实例。真实 GPU 验证需另有当次授权，本次没有执行。
